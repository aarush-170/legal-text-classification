# Legal Text Classification: US Supreme Court issue areas (LexGLUE SCOTUS)

Classify US Supreme Court opinions by issue area, following the Stanford CS229 report
["Classification of Legal Text"](https://cs229.stanford.edu/proj2020spr/report/Iyer.pdf) (Iyer, 2020).
We reproduce its classical baselines (LDA / Doc2Vec + logistic regression), add a strong TF-IDF baseline and a
chunked Legal-BERT that handles the very long opinions that made plain BERT run out of memory, and ship a demo
that **explains** each prediction and **retrieves similar past cases**.

## Data
LexGLUE SCOTUS (Chalkidis et al., ACL 2022), loaded from the `lighteval/lexglue` parquet files.
Verified by `python -m src.eda --dataset scotus` (see `results/eda_scotus.json`):

| | train | dev | test |
|---|---|---|---|
| opinions | 5,000 | 1,400 | 1,400 |
| median words | 4,365 | 7,591 | 6,883 |

- **13 classes, not 14.** SCDB issue area 14 ("Private Action") never occurs; the data uses codes 1-13.
- **Heavily imbalanced.** Largest class 26.6% of test; "Miscellaneous" has 3 train / 10 dev / 3 test opinions.
- **Very long.** Mean 5.9k words (train) to 8.7k (test), max 89k: far beyond BERT's 512 tokens.
- **Train opinions are shorter than dev/test** (likely a temporal split), which partly explains the dev-to-test drop.
- No empty texts; no exact duplicates across splits.

## Run (one command per step)
```bash
python -m src.data --dataset scotus                       # download parquet files to data/raw/ (~173 MB)
python -m src.eda --dataset scotus                        # EDA stats + plots -> results/
python -m src.baselines --dataset scotus --model tfidf    # TF-IDF + LR (~6 min CPU)
python -m src.topic_baselines --dataset scotus --model lda       # ~8 min CPU
python -m src.topic_baselines --dataset scotus --model doc2vec   # ~6 min CPU
python -m src.transformer --dataset scotus --mode embed          # frozen Legal-BERT + LR (GPU)
python -m src.transformer --dataset scotus --mode finetune       # fine-tune, mean of chunk logits (GPU, 1-2 h)
python -m app.app                                          # demo at http://127.0.0.1:7860
```
Every script takes `--quick` for a tiny smoke test that saves nothing. The transformer runs on a Colab GPU via
`notebooks/colab_transformer.ipynb`. Hyper-parameters are tuned on **dev only**; test is scored once. Seed is 42.

### Comparison with published LexGLUE results
From Chalkidis et al. (2022), Table 3, SCOTUS (micro-F1 / macro-F1, %; see `results/lexglue_published_scotus.csv`):
TFIDF-SVM 74.0 / 64.4; Legal-BERT (hierarchical) 76.4 / 66.5; CaseLaw-BERT (hierarchical) 76.6 / 65.9.
Our TF-IDF + LR (73.8 / 62.8) is close to the paper's TFIDF-SVM. The comparison is indicative, not like-for-like
(different preprocessing, classifier, and the paper averages neural models over seeds).

### Analysis
- **TF-IDF beats LDA and Doc2Vec by about 11 accuracy points** and is the strongest classical model. This does
  not reproduce the CS229 report's finding that Doc2Vec was the best baseline. Doc2Vec beats LDA on macro-F1
  (0.454 vs 0.415) but is level on accuracy. Caveat: we tuned Doc2Vec/LDA lightly (fixed dimension, 10 LDA iterations).
- **Dev-to-test drop** (TF-IDF: 0.791 to 0.738 accuracy, 0.717 to 0.628 macro-F1), consistent with the
  length shift above and with very small classes making macro-F1 noisy.
- **Per-class (TF-IDF, test F1):** strong on Criminal Procedure (0.86), First Amendment (0.86) and Interstate Relations
  (0.85); weak on Federalism (0.29), Privacy (0.42) and Miscellaneous (0.00, only 3 test opinions).
- **Label noise:** SCDB issue areas overlap (e.g. immigration cases appear under both Civil Rights and Criminal
  Procedure), so some "errors" are defensible predictions.

## Demo (`app/app.py`)
Paste an opinion (or load a random test opinion) to get:
1. the predicted issue area with confidence;
2. the passages that most drove the prediction. TF-IDF + LR is linear, so each sentence's contribution to the
   predicted class's logit is an exact sum over its words (`src/explain.py`);
3. the top-5 most similar training cases with their true labels (cosine similarity; Legal-BERT embeddings when
   `models/scotus_legalbert_embeddings.npz` exists, otherwise TF-IDF).

Limitations: explanations describe the TF-IDF model, not the transformer; retrieval similarity is lexical when
running on the TF-IDF fallback; the demo is a research prototype, not legal advice.
